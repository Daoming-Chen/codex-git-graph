# 故障排查

## 插件入口没有出现

先确认已执行 `npm run build`，marketplace 条目指向实际插件目录，并已重启 Codex、安装插件。原生 MCP Apps 按钮是否显示取决于宿主版本，尚未完成真实桌面宿主的端到端验证。

可在目标仓库聊天中请求打开 Git Graph，使用工具返回的完整 `panelUrl`。仍无法加载插件时，按 [README](../README.md#开始使用)直接启动 HTTP 面板，保留错误信息供排查。

## 链接失效或连接中断

直接启动的服务需要保持终端运行。插件服务重启或回收后，旧链接和令牌会失效；重新打开 Git Graph，使用新返回的完整链接，不要手动拼接令牌。

关闭标签页不一定立即关闭后台服务。服务会回收闲置面板；全部服务都忙碌时，新面板可能提示稍后重试。

如果连接在写操作期间中断，先检查实际 HEAD、工作区和进行中的 Git 操作，再决定是否继续。插件不会自动重试结果未知的写操作。

## 打开的仓库不对，或要求选择仓库

本机桌面宿主的固定入口会尝试按当前聊天自动识别仓库；新建聊天入口没有持久化记录时，尝试读取当前选中的本地项目。正常使用无需输入绝对路径。已有聊天的工作目录优先于全局项目选择，插件安装目录不会作为目标仓库。

仍要求选择时，检查插件是否已重新加载最新构建，以及服务进程是否有权读取 `CODEX_HOME`（默认 `~/.codex`）中的聊天索引和项目记录。本机适配依赖宿主的非标准存储格式及 `node:sqlite`；其他宿主仍可通过 MCP roots 提供仓库。多个候选、没有可用仓库或读取失败时，面板可能要求选择；多窗口的新建聊天入口尚未验证。解析顺序与限制见[架构与安全边界](current-implementation.md#仓库上下文与请求隔离)。

直接启动 HTTP 服务时，显式传入 `--repo`。不传时，服务先使用 `GIT_GRAPH_REPO`，再使用进程当前目录。

## 工作记录读取失败或提交没有关联

出现「工作记录读取失败」时，检查当前仓库根目录的 `.workgraph.json` 是否为有效 JSON，核对文件类型、大小和工作项字段，并检查提交关联是否重复。格式与限制见 [WorkGraph 使用说明](work-graph.md)。读取失败不会回退到演示数据；修正后点击「刷新」。

未配置工作记录时，历史提交归入「未关联的提交」。已有记录但提交仍未关联时，核对完整 SHA 或提交正文中的 `Work-Item` 标识是否匹配工作项。工作视图只读取当前 HEAD 最近 300 条提交，其他历史需切换到「Git 历史」查看。历史重写后需要手动核对并更新 SHA。

## 远程操作失败

记录面板中的 Git 错误，核对 Remote、分支和本机认证。读取本地历史不要求 GitHub 或 GitLab 登录。普通提交失败时，检查本机 hook 或签名错误，不要通过跳过检查掩盖失败。

诊断会遮盖部分常见凭据格式，但任意 hook 仍可能输出私密内容。分享日志前检查并删除凭据、仓库私有地址和敏感文件内容。

## SSH、WSL 或跨主机面板打不开

回环链接指向运行服务的机器，桌面浏览器不一定能访问。先检查宿主是否支持 MCP Apps 面板；这些执行环境尚未验证。不要为解决访问问题公开仓库服务或创建公网隧道。

## 配置无法保存或恢复

仓库配置位于 Git common dir，布局偏好位于浏览器，详见[使用指南](usage.md#设置与审阅进度)。无效、超限或符号链接形式的仓库配置文件会被拒绝，不会静默覆盖。先记录错误并检查文件，不要直接删除尚需保留的配置。
