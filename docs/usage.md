# 使用指南

先按[安装说明](install-lifecycle.md)打开目标仓库。面板中的写操作会调用本机 Git，普通提交遵循本机 hooks 和签名配置。

## 浏览历史与比较

面板默认打开「工作进展」，展示仓库的工作记录和关联提交。工作状态筛选、搜索、刷新和配置方法见 [WorkGraph 使用说明](work-graph.md)。需要执行 Git 操作或浏览其他分支时，点击顶部「Git 历史」；点击「工作进展」可返回。以下说明对应 Git 历史界面。

选择提交查看详情和文件差异；合并提交可以选择用于比较的父提交。设置两个比较端点时，差异方向为 A 树到 B 树；也可以将历史提交与操作工作区比较。

历史默认加载 300 条，每次续载 300 条。查找只覆盖已加载记录；需要更早的提交时先继续加载。可按引用、分支通配符、第一父提交和 reflog 筛选，并调整远程、标签和 Stash 引用的显示。

未跟踪文本、文件内容与 diff 的预览上限为 256 KiB；二进制文件和子模块会显示提示。文件查看在面板内完成，不是编辑器集成。

## 审阅文件并提交

1. 核对操作 Worktree，打开工作区文件清单。
2. 逐文件审阅差异，明确选择需要暂存的文件，再执行暂存。
3. 核对已暂存内容，输入提交消息并检查操作摘要。
4. 确认执行。提交只包含 index 中的内容，未暂存修改保留在工作区。

空仓库也可审阅文件并创建首次提交。丢弃修改、清理未跟踪文件和历史重写可能造成内容丢失，应先核对目标和后果。

## 分支、同步与冲突

| 对象 | 支持的操作 |
| --- | --- |
| 分支与提交 | 创建、切换、重命名和删除分支；检出提交；创建远程跟踪分支 |
| 标签 | 创建、查看详情、签名、删除与推送 |
| Remote 与同步 | Remote 增改删、Prune、Fetch、Pull（快进／合并／变基）、普通 Push、设置上游、删除远程分支 |
| 历史 | Merge、Rebase、Cherry-pick、Revert、Reset、线性历史 Drop |
| Stash | 保存、应用、弹出、删除、恢复 index、创建分支 |
| 工作区 | 指定文件丢弃修改、清理未跟踪文件；冲突文件标记解决；继续／中止进行中的操作 |

Fetch 前看到的远程引用只是本地最近获取的状态；同步前核对 Remote 和目标分支。远程操作沿用本机 Git 认证。远程分支删除绑定最近获取的 SHA，远程分支变化时会拒绝执行。

发生冲突时，在外部编辑器修改文件内容，再刷新面板、标记解决，并选择继续或中止进行中的操作。面板不提供冲突编辑器。Drop 只支持当前分支上的单父线性提交，不支持根提交或跨合并链。

操作失败时输入会保留。超时或连接中断可能表示结果未知：先核对实际 Git 状态，再决定下一步，不要直接重复执行。

## 多个 Worktree 与仓库切换

创建 Worktree 时使用新分支和新目录。分支被其他 Worktree 占用时，面板会识别占用状态。

本机原生 MCP Apps 面板优先识别当前聊天的工作目录；新建聊天入口尝试使用当前选中的本地项目，正常打开无需填写路径。其他宿主可通过 MCP roots 提供上下文；上下文不唯一时需选择仓库。本机适配的兼容性与多窗口限制见[架构与安全边界](current-implementation.md#仓库上下文与请求隔离)。切换会清空详情、筛选、勾选文件、提交消息及已准备操作。切换不能撤销已在服务端开始的 Git 操作，结果未知时需回原仓库核对。

通过回环链接打开的面板固定绑定打开时的仓库，不随聊天切换。

## 设置与审阅进度

仓库配置和审阅进度保存在 Git 共用目录（Git common dir）的 `workgraph-state.json`，同一仓库的 Worktree 共用，重启服务后仍可读取。界面若仍显示「保存在此浏览器」，实际存储位置以本段为准。

仓库配置包括 Issue／PR URL 模板、日期格式、滚动续载、目录分组，以及作者／日期／SHA 列宽。配置导入／导出不包含审阅进度。审阅记录按比较两端的提交 SHA（根提交比较的一端使用 `root`）保存，超过 90 天的记录在读取或保存时过滤；历史与工作目录比较没有相同的审阅标记入口。

主题、列显隐和详情位置等布局偏好另存于浏览器，服务端口改变后不保证恢复。
