# 工作视图交互原型

默认进入「工作进展」演示。界面沿用真实 Git 图的配色、紧凑行、节点轨道和底部详情，用于验证跨会话工作及成果的组织方式。

## 运行与体验

运行 `npm run build`，再运行 `npm start -- --repo "仓库绝对路径"`，打开服务输出的完整链接。

默认停在暂停阶段。顶部两行显示各项工作的当前状态，下方按时间倒序显示成果、恢复点和续接记录。彩色轨道连接同一项工作的记录；方形节点表示成果，空心节点表示恢复点。两项独立工作之间没有连线。

选择一行，在底部查看上下文与验证依据。「继续工作」位于详情标题旁，可进入隔天续接阶段，再点击「验证并完成」体验完成状态。工作完成、验证、集成和用户接受分别表达。目标、关键决定、分支和文件路径按需展开。

「展开记录」显示目标、决定、验证和集成事件。「代码与差异」支持选择演示文件。状态筛选与搜索可缩小列表；没有结果时清空详情。

右上角「演示」收纳阶段选择、下一阶段和从头体验：

1. 开始「按文件筛选差异」。
2. 中途独立修复空仓库启动问题。
3. 修复完成，暂停原功能并保留现场。
4. 隔天续接同一工作项。
5. 验证完成并集成，用户接受仍为未记录。

顶部「真实 Git」进入现有仓库视图；「工作 · 演示」返回原型。切换保留双方页面状态。「主题」可检查深浅配色。

## 数据边界

所有工作、日期、文件、验证、恢复点和提交标识均为演示数据，不代表当前仓库事实。`demo:` 标识不是实际提交 SHA；差异片段不能应用为补丁。

原型状态仅保存在页面内存，刷新后重置。继续、完成、阶段切换和查看差异不调用 Git 接口，不修改真实文件、分支或提交。工作模式隐藏真实 Git 工具栏并隔离其快捷键；真实 Git 模式保留原有操作。

轨道表达同一工作的推进与成果归属，不表达 Git 提交父子关系。本例两项工作独立存在，没有工作拆分或依赖关系。当前原型未实现真实工作项持久化、自动归类、自动提交、恢复或用户接受确认。
